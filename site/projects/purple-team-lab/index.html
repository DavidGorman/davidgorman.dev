Overview

A home lab modelled on a fictional small business, with a firewalled DMZ, an internal Active Directory network and a dedicated management segment for monitoring. It brings networking, systems administration, SIEM engineering, offensive testing, hardening and reporting together in one project.

Problem

The scenario: an attacker breaches a public-facing web server in the DMZ, then tries to pivot into the internal Active Directory network. The firewall rules decide whether that pivot succeeds. The hardening phase then fixes both the web vulnerability and the internal weaknesses, and every change is validated by attacking again.

Approach

pfSense is the only route between segments, with default-deny rules between them. Each attack technique goes through the same loop:

  1. Attack from Kali using a named technique
  2. Map it to MITRE ATT&CK
  3. Hunt for it in the SIEM
  4. Detect it with a rule that fires on it
  5. Harden the target
  6. Re-attack to prove the fix and the detection both work

Hardening targets ASD Essential Eight Maturity Level One, with network design guided by the ASD Information Security Manual and CIS Benchmarks. Wazuh is installed and configured by hand rather than from a prebuilt image, and every configuration change is recorded in a change log with before and after evidence.

Roadmap

The project runs in six phases. Live progress is tracked on the sprint board.

  1. Build (current): all machines are installed; next is configuring the network, firewall rules, the domain and each server
  2. Monitor: install Wazuh by hand and bring logs in from every host
  3. Attack: run each scenario from Kali and record what succeeds
  4. Harden: fix the weaknesses the attacks exposed, working towards Essential Eight Maturity Level One
  5. Re-test: repeat every attack to prove each fix works
  6. Report: write up the findings, evidence and before and after results

Planned scenarios

Web server breach and pivot

The core scenario described above: compromise the vulnerable web app in the DMZ, then try to move into the internal Active Directory network, with the firewall rules deciding whether the pivot succeeds.

Assume breach: data exfiltration

An attacker already has a foothold inside the network, as if a phishing email had worked, and tries to get data out. The goal is to harden egress so it fails: filtering outbound traffic, forcing DNS through an internal resolver, and closing common exfiltration channels such as DNS tunnelling, HTTPS uploads and cloud storage. The phishing lure is built for the report only and never sent. The response is run as a live incident, from triage to a written situation report.

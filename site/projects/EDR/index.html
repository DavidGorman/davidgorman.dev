Project

Endpoint Detection and Response

A lightweight, customisable endpoint detection and response tool written in Python, built by a five-person team for an industry client.

Overview

A rule-based EDR for Linux, with modules for file monitoring, process inspection, network monitoring and log analysis, plus automated responses: process kill, file quarantine and IP block. Every detection is mapped to MITRE ATT&CK.

Problem

The client needed a customisable, scalable EDR they could deploy on Linux virtual machines to measure how effective their attack simulations were.

Approach

We took an attack-first approach. Brute-force, SQL injection, file upload and remote code execution (RCE) attacks were run from Kali Linux against OWASP Juice Shop on an Ubuntu server, telemetry was collected, and detections were built from that data. Each team member owned one attack, its telemetry and its detection module.

As technical lead I designed how telemetry was collected from everyone's attacks, built the core detection engine, and wrote the RCE detection module, which detects remote code execution achieved through server-side template injection. Performance was measured as Mean Time to Detect (MTTD) against a Wazuh baseline.

Outcome

Across two evaluation runs on separate lab setups, the RCE module detected every RCE attack with no false positives. In the final run it matched Wazuh on detection and was slightly faster to alert.

RCE detection, final run: 3 malicious and 3 benign test cases
MetricEDR (RCE module)Wazuh
Attacks detected3 of 33 of 3
False positives0 of 30 of 3
Mean time to detect1.14s1.25s

Across all five attack types in the final run (12 malicious and 20 benign cases), both tools caught the same 6 of 12 attacks. The EDR raised 2 false positives against Wazuh's 7, mostly because its rules were written for this specific application. The full per-attack results are in the repository README.

The EDR was also built to stay light on the endpoint. Running side by side with the Wazuh agent, it used about a third of the memory.

In the other test setup, the Wazuh manager ran on the same VM, so its figure (about 534 MB) isn't a like-for-like comparison and isn't used here.

Limitations

  • The sample is small. For RCE, 100% detection means 3 of 3 attacks in one lab run, not evidence of production-grade accuracy.
  • File upload detection didn't fire in the final run (0 of 4), and the forged-token rule missed 2 of 3 cases. Both are open issues.
  • The rules are tuned to OWASP Juice Shop and would need rewriting for a different application.
  • Only one host was monitored, with no central management, and detection speed depends on a 2-second poll interval.
